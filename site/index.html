How it works

Kane is the judge at every step

  1. Record the test onceYou describe the flow in plain words. Kane performs it in a real browser on the version that worked and records it.
  2. Search the historyCulprit jumps through your commits, halving the range each time, and replays the recording on each one. A replay takes seconds.
  3. Name the culpritIt double-checks the answer. If the checks disagree it says “inconclusive” instead of guessing.
  4. Fix it, and let Kane prove itUndo the commit, or let an agent patch it. Kane replays the same test, and nothing is kept that Kane did not confirm.

The closed loop

Fail. Fix. Prove.

Kane: FAILon the broken commit
→
Culprit: fixundo, or agent patch
→
Kane: PASSsame test, same recording

If a plain undo conflicts with later commits, the agent gets Kane’s failing step as evidence and proposes a patch. If Kane still says no, Kane’s new evidence goes back to the agent for another try, up to three. A patch that edits the test is rejected, so a bug can’t be “fixed” by weakening the test.

Why you can trust the answer

Built so Kane can’t be fooled, and neither can you

Self-healing is off

Kane can auto-repair a failing step, which could turn a real bug into a pass. Every check runs with healing disabled.

Errors are never blamed on a commit

If Kane times out or glitches, that check is skipped and the run stops. It never accuses a commit because of an error.

Reliability comes first

Before searching, the ends of the range are replayed to make sure the test is stable. On the demo test: 10 passes, 10 failures, no errors.

The test can’t be weakened

Any fix that touches the test files is rejected and rolled back.

Questions

What does Culprit do?

When a browser flow starts failing, it finds the commit that broke it, undoes that commit (or has an agent patch it), and replays the same test to prove the flow works. Halving the range means 15 commits take about 4 checks instead of up to 15.

How is this different from git bisect?

Same idea, applied to browser flows. Culprit adds what makes a browser result trustworthy: self-healing off, errors never blamed on a commit, a double-checked answer, and a guard on the test files. And Kane means the test is plain English, not a script you maintain.

What can I run on my own repo?

Public GitHub repos that are static sites: HTML, CSS and JavaScript, with an index.html in the root or in a public, docs, dist or build folder. Culprit serves the site itself and never installs or builds your code. Apps that need a server or a build step are not supported yet.

Does an AI write the fix?

By default the fix is a plain git revert of the culprit, re-checked by Kane. When the server has an agent configured and a plain undo conflicts, the agent proposes a small patch and Kane has the final say.

Is the demo real or staged?

Both, and labelled. The Kane results from Nov 16 are real. The demo shop’s commit history is made up, with one planted bug. The badge at the top of every page says whether this server runs real Kane or a stand-in.

Does it cost Kane credits?

Recording a test uses credits; replays reuse the recording. To keep the free credits lasting, each visitor gets a few runs a day. The recorded real run is always free.
